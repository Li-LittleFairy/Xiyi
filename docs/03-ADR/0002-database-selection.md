# ADR-0002：本机演示阶段的数据库选型

- 状态：已采纳
- 提议日期：2026-11-18
- 采纳日期：2026-11-19
- 决定人：项目用户
- 依据：询问是否按本机已有 MySQL 生成建表脚本后，用户选择“使用已有 MySQL（推荐）”。本轮明确只生成脚本，不连接或改动现有数据库。
- 关联：ADR-0001

## 背景

当前原型使用浏览器存储。正式实现需要持久保存客户、订单、衣物明细、收款和操作记录。用户已选择本机开发演示。2026-11-19 检测到 PATH 中的 MySQL 客户端版本8.0.44及正在运行的 MySQL Windows 服务；没有连接服务端或读取数据库内容。

## 候选方案

1. SQLite：减少独立数据库服务管理，适合优先跑通本机轻量流程；需验证驱动、事务、迁移与备份，以及目标并发是否适合。
2. 本机 MySQL 或 PostgreSQL：使用独立数据库服务；需要管理安装、账号、连接和备份。若采用此方向，再确定具体产品和兼容版本。

## 决策依据

根据当前阶段更重视轻量演示还是独立数据库实践、已有环境、预期并发和后续部署方向做选择。不要仅因“未来可能上云”或“现在在本机”就自动决定数据库。

## 决定与理由

使用本机现有 MySQL 作为开发数据库方向，并按 MySQL 编写一期七张核心表的建表脚本。复用已有安装，避免另行准备数据库产品，同时采用独立数据库服务完成本机开发。

脚本针对 MySQL 8.0.16+ 的约束能力编写；客户端版本不等于已核实的服务端版本，实际执行前必须检查。此决定不授权安装软件、连接其他业务库、创建正式数据库或修改全局环境。

## 后果与验证

2026-11-19 后续授权：用户指定正式工作空间 `D:\Project\TestProject\xiyi` 并明确“可以建表了”。此前只生成脚本的限制不再阻止在项目专用开发库执行；执行仍需明确连接及目标库，不涉及其他业务库。

需要配置专用开发库、账号和连接，使用 InnoDB事务、外键及版本化迁移，并准备备份恢复。2026-11-19已在新建专用库xiyi_dev执行 `database/mysql/V001__create_core_tables.sql`；服务端8.0.44，数据库层8项正常断言和10项异常约束检查通过，测试后七表为空；详见 `docs/04-组件说明/database-mysql/execution-2026-11-19.md`。MySQL DDL不能作为整份脚本的一次普通事务回滚。

字段及业务规则草案见 `docs/02-开发文档/data-model-v1.md`。建表、约束、数据持久化和事务并发验证按 `docs/04-组件说明/database-mysql/README.md` 后续完成。迁移工具尚未选定。
