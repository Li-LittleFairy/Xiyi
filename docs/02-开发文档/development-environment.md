2026-11-19 更新：用户已选择本机现有 MySQL，依据 ADR-0002。已核验服务端8.0.44，并创建xiyi_dev库及七张表，数据库层验证通过。见 `docs/02-开发文档/data-model-v1.md` 与 `docs/04-组件说明/database-mysql/README.md`。

## 一、服务器、后端和数据库的区别

- 后端服务是运行的程序，例如 Spring Boot 应用，负责接口和业务处理。
- 承载服务的机器可以是自己的电脑、店内电脑或远程服务器。现阶段使用自己的电脑，无需购买云服务器。
- 数据库负责持久保存数据。它可以是嵌入应用使用的数据库，也可以是独立运行的数据库服务，不要求单独买一台机器。
- 前端是浏览器看到的界面，可以与后端在同一台电脑运行。

目标关系：本机浏览器 → 本机后端 → 本机数据库。当前原型只是浏览器内的模拟流程，这条真实链路尚未建立。

## 二、现在要准备的项目

| 项目 | 当前安排 | 验证标准 |
| --- | --- | --- |
| JDK | 后端初始化时选择与 Spring Boot 兼容的版本 | 可编译和启动应用 |
| 构建工具 | 选择一种并固定项目版本，提供可重复构建入口 | 按说明可构建，无需猜本机配置 |
| 前端工具 | 简单静态前端可由后端提供；若使用构建工具再准备 Node 等依赖 | 页面能请求真实后端 |
| 数据库 | 已创建MySQL 8.0.44的xiyi_dev专用库及七张表；待接入应用驱动、专用账号和迁移工具 | 写入、查询、重启保留数据 |
| 环境配置 | 明确开发配置、数据位置、端口和启动顺序；密钥通过外部配置注入 | 换目录或新环境仍能按说明启动 |
| 代码管理 | 初始化时检查现有仓库边界，确定正式代码位置和忽略规则 | 源码可追踪，数据文件和密钥不误提交 |
| 演示数据 | 使用固定、虚构且可重复生成的数据 | 能稳定复现验收场景 |
| 备份与恢复 | 按最终数据库方案编写步骤 | 从备份恢复后能核对订单、收款等数据 |

开发服务默认限制为本机访问；端口及确切版本在初始化时检查环境后记录。本次未安装新软件；已使用现有服务创建xiyi_dev及七张表，执行结果见docs/04-组件说明/database-mysql/execution-2026-11-19.md。

## 三、选型时的候选比较（历史依据）

| 方案 | 适用方向 | 需要付出的工作 |
| --- | --- | --- |
| SQLite | 本机轻量演示，减少数据库服务的安装管理 | 确认驱动、迁移和备份方法；评估后续并发及部署需求 |
| 本机 MySQL 或 PostgreSQL | 希望从开始就使用独立数据库服务，并练习账号、连接和运维 | 安装服务、初始化库与账号、配置连接及备份，管理开发环境 |

本机开发并不强制使用 SQLite；以后换数据库也不能假定毫无成本。现已选MySQL，理由与状态以ADR-0002为准，不再同时准备其他数据库实现。

## 四、正式部署前再明确

确定实际访问范围、设备数量、数据量和可用性要求；然后选择目标机器、网络和运维方式。若面向公网，再准备适合该访问方式的域名/HTTPS、访问控制和网络配置。

还需明确服务自动启动、日志、故障处理、数据库权限、备份保留和恢复责任。数据库原则上由后端访问，不让顾客浏览器直接连接数据库。
